Tools 系统：Claude 可调用的能力

Tools（工具）是 Claude Code 与外部世界交互的桥梁，让 Claude 能够读写文件、执行命令、搜索代码，真正成为一个有行动能力的助手。

1. 什么是 Tools

1.1 定义

Tools 是 Claude 可以调用的函数，每个工具封装了一个特定的能力（如读取文件、执行命令）。通过工具，Claude 从”只能对话”变成”能够行动”。

1.2 工具 vs 普通函数

特性 普通函数 Claude Tools
调用者 代码 AI 模型
参数 编译时确定 运行时推断
描述 可选 必需（供 AI 理解）
权限 代码控制 用户授权

2. 工具调用机制

2.1 调用流程

sequenceDiagram
    participant U as 用户
    participant C as Claude
    participant TD as Tool Dispatcher
    participant T as 具体工具
    participant PC as Permission Controller
    
    U->>C: 请求（如"读取 config.json"）
    C->>C: 分析需求，选择工具
    C->>TD: 调用 Read 工具
    TD->>PC: 检查权限
    
    alt 需要授权
        PC->>U: 请求授权
        U->>PC: 授权/拒绝
    end
    
    alt 授权通过
        TD->>T: 执行工具
        T-->>TD: 返回结果
        TD-->>C: 传递结果
        C->>C: 分析结果，继续推理
        C->>U: 输出响应
    else 授权拒绝
        TD-->>C: 操作被拒绝
        C->>U: 说明情况
    end

2.3 工具选择逻辑

Claude 基于以下因素选择工具：

  1. 任务类型：读取文件 → Read，搜索代码 → Grep
  2. 参数匹配：用户提供的信息是否足够
  3. 上下文：之前的操作结果
  4. 效率：选择最直接的工具
flowchart TB
    Input[用户请求] --> Analyze[分析需求]
    Analyze --> Match{匹配工具}
    
    Match -->|读取文件| Read[Read]
    Match -->|修改文件| Edit{修改类型}
    Edit -->|新建/覆盖| Write
    Edit -->|局部修改| StrReplace
    
    Match -->|搜索| SearchType{搜索类型}
    SearchType -->|精确文本| Grep
    SearchType -->|文件名| Glob
    SearchType -->|语义| SemanticSearch
    
    Match -->|执行命令| Shell

3. 内置工具详解

3.1 文件操作工具

Read - 读取文件

功能：读取文件内容

参数：

参数 类型 必需 说明
path string ✅ 文件绝对路径
offset number ❌ 起始行号
limit number ❌ 读取行数

示例：

支持的文件类型：

  • 文本文件（代码、配置、文档）
  • 图片（jpeg, png, gif, webp）
  • PDF（自动转换为文本）

最佳实践：

  • 大文件使用 offset 和 limit 分段读取
  • 图片文件直接读取，无需特殊处理

Write - 写入文件

功能：创建或覆盖文件

参数：

参数 类型 必需 说明
path string ✅ 文件绝对路径
contents string ✅ 文件内容

示例：

注意事项：

  • 会覆盖已存在的文件
  • 自动创建父目录
  • 优先使用 StrReplace 进行局部修改

StrReplace - 字符串替换

功能：在文件中精确替换文本

参数：

参数 类型 必需 说明
path string ✅ 文件绝对路径
old_string string ✅ 要替换的原文本
new_string string ✅ 替换后的新文本
replace_all boolean ❌ 是否替换所有匹配

示例：

关键规则：

  • old_string 必须在文件中唯一存在
  • 如果有多处匹配，需要包含更多上下文使其唯一
  • 或使用 replace_all: true 替换所有

Delete - 删除文件

功能：删除指定文件

参数：

参数 类型 必需 说明

3.2 搜索工具

Grep - 正则搜索

功能：在文件中搜索匹配正则表达式的内容

参数：

参数 类型 必需 说明
pattern string ✅ 正则表达式模式
path string ❌ 搜索路径
glob string ❌ 文件过滤模式
type string ❌ 文件类型（js, py, java…）
-i boolean ❌ 忽略大小写
-A number ❌ 显示匹配后 N 行
-B number ❌ 显示匹配前 N 行
-C number ❌ 显示匹配前后 N 行

示例：

输出模式：

  • content（默认）：显示匹配行内容
  • files_with_matches：只显示文件路径
  • count：显示匹配计数

Glob - 文件查找

功能：按模式查找文件

参数：

参数 类型 必需 说明
glob_pattern string ✅ Glob 模式
target_directory string ❌ 搜索目录

示例：

常用模式：

  • *.ts - 当前目录所有 .ts 文件
  • **/*.ts - 递归所有 .ts 文件
  • src/**/*.{ts,tsx} - src 下所有 ts/tsx 文件
  • !**/node_modules/** - 排除 node_modules

SemanticSearch - 语义搜索

功能：通过自然语言查询搜索代码

参数：

参数 类型 必需 说明
query string ✅ 自然语言查询
target_directories string[] ❌ 搜索目录列表
num_results number ❌ 返回结果数量（最大 15）

示例：

适用场景：

  • 探索陌生代码库
  • 查找功能实现
  • 理解代码逻辑

不适用场景：

  • 精确文本搜索（用 Grep）
  • 查找特定文件（用 Glob）

9. 常见问题

Q: 为什么推荐 StrReplace 而不是 Write？

A:

  • StrReplace 只修改需要改变的部分，保留其他内容
  • Write 会完全覆盖文件，容易丢失内容
  • StrReplace 更适合代码审查（diff 更清晰）

Q: Grep 和 SemanticSearch 如何选择？

A:

  • Grep：知道要搜索什么（精确文本、正则表达式）
  • SemanticSearch：不知道具体实现，按功能查找

Q: Shell 命令超时怎么办？

A:

  1. 设置 block_until_ms: 0 后台运行
  2. 增加 block_until_ms 值
  3. 拆分为多个小命令
