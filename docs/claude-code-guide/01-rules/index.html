Rules 系统：持久化的行为约束

Rules 是 Claude Code 最基础也最重要的配置机制。通过 Rules，你可以定义项目的”宪法”——Claude 在每次对话中都会遵循的行为准则。

1. 概述

1.1 什么是 Rules

Rules（规则）是一组持久化的指令，它们会被自动注入到每次对话的系统提示（System Prompt）中，让 Claude 在整个会话期间始终遵循这些约束。

1.2 Rules 的作用

场景 没有 Rules 有 Rules
每次对话 需要重复说明技术栈、规范 Claude 自动了解项目背景
代码风格 可能生成不符合规范的代码 始终遵循团队约定
错误处理 可能忽略项目特有的坑 会主动避开已知问题

1.3 Rules vs Skills

graph LR
    subgraph Rules
        R1[始终生效]
        R2[注入系统提示]
        R3[定义"是什么"]
    end
    
    subgraph Skills
        S1[按需加载]
        S2[用户或模型触发]
        S3[定义"怎么做"]
    end
    
    R1 -.->|区别| S1
    R2 -.->|区别| S2
    R3 -.->|区别| S3

简单理解：

  • Rules = 项目的”身份证”（Claude 必须知道的背景信息）
  • Skills = 项目的”工具箱”（Claude 可以使用的专业技能）

2. 核心概念

2.1 Rules 的加载机制

sequenceDiagram
    participant U as 用户
    participant CC as Claude Code
    participant FS as 文件系统
    
    U->>CC: 启动会话
    activate CC
    
    CC->>FS: 查找 CLAUDE.md
    FS-->>CC: 返回内容
    
    CC->>FS: 查找 .claude/rules/*.md
    FS-->>CC: 返回所有规则文件
    
    CC->>CC: 合并所有规则到系统提示
    
    CC->>U: 会话就绪
    deactivate CC
    
    Note over CC: 之后每次对话都带有这些规则

2.2 文件位置与优先级

Claude Code 会在以下位置查找 Rules（按优先级从高到低）：

位置 文件 作用范围 优先级
当前目录 CLAUDE.md 子目录特定 最高
项目根目录 CLAUDE.md 整个项目 高
项目根目录 .claude/rules/*.md 模块化规则 中
用户主目录 ~/.claude/CLAUDE.md 所有项目 低

2.3 路径匹配规则

.claude/rules/ 目录下的规则文件支持路径匹配，让规则只对特定文件生效：

匹配规则：

  • * - 匹配单层目录中的任意字符
  • ** - 匹配任意层级目录
  • *.java - 匹配所有 Java 文件

3.3 编写原则

原则 说明 示例
具体 避免模糊描述 ❌ “代码要规范” → ✅ “方法不超过 50 行”
可执行 Claude 能据此行动 ❌ “注意性能” → ✅ “N+1 查询必须用 @BatchSize 解决”
有示例 展示而非仅告知 ❌ “用 Result 包装” → ✅ “返回 Result.ok(data)“
保持更新 定期同步实际情况 添加新技术时更新技术栈部分

4. 模块化规则（.claude/rules/）

4.1 为什么需要模块化

当项目变大时，单个 CLAUDE.md 会变得臃肿。模块化规则让你可以：

  • 按职责拆分：API 规范、测试规范、安全规范各自独立
  • 按路径生效：前端规则只在前端目录生效
  • 便于维护：修改一个规则不影响其他

7. 最佳实践

7.1 应该放入 Rules 的内容

✅ 推荐：

  • 技术栈和版本信息
  • 代码规范和约定
  • 项目结构说明
  • 常用命令
  • 已知问题和解决方案
  • 安全相关的禁忌

7.2 不应该放入 Rules 的内容

❌ 避免：

  • 敏感信息（密钥、密码）
  • 频繁变化的内容
  • 过于细节的实现逻辑
  • 与当前项目无关的通用知识

7.3 维护建议

频率 动作
每次提交 检查是否需要更新 Rules
每周 审视 Rules 是否与实际一致
技术栈变更时 立即更新相关版本信息

8. 常见问题

Q1：CLAUDE.md 不生效？

检查：

  1. 文件名是否正确（区分大小写）
  2. 文件是否在项目根目录
  3. 文件内容是否有语法错误

Q2：规则太多导致上下文过长？

解决：

  1. 使用 .claude/rules/ 模块化，配合 globs 限制作用范围
  2. 移除不必要的详细说明
  3. 将”怎么做”的内容移到 Skills

Q3：多人协作时 Rules 冲突？

建议：

  1. 在团队内讨论并统一规范
  2. 使用 .claude/rules/ 按职责拆分，减少冲突
  3. 将 Rules 纳入 Code Review 范围

Q4：如何调试 Rules 是否生效？

Claude 会输出它理解的规则，你可以据此判断哪些生效了。
