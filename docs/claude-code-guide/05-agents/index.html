Agents 系统：专业化代理

Agents（代理）是 Claude Code 的分身能力，允许你创建专注于特定任务的独立 Claude 实例，实现并行处理和专业化分工。

1. 什么是 Agents

1.1 定义

Agents（代理）是 独立运行的 Claude 实例，拥有自己的上下文和工具访问权限，可以执行特定领域的任务。

1.2 为什么需要代理

场景 无代理 有代理
多任务处理 顺序执行，效率低 并行执行，速度快
上下文隔离 所有任务共享上下文，容易混乱 每个任务独立上下文，清晰
专业分工 通用提示，质量不稳定 专业提示，质量有保障
错误隔离 一个任务失败影响全局 失败仅影响单个代理

1.3 核心概念

    subgraph "主代理 (Main Agent)"

    end

适用于：

  • 代码审查
  • 质量检查

5. 代理通信机制

5.1 数据流

sequenceDiagram
    participant MA as 主代理
    participant TM as Task Manager
    participant SA as 子代理
    
    MA->>TM: 创建任务 (prompt, type, ...)
    TM->>SA: 初始化子代理
    TM->>SA: 注入代理配置
    TM->>SA: 传递任务 prompt
    
    loop 任务执行
        SA->>SA: 规划与执行
        SA->>SA: 调用工具
    end
    
    SA->>TM: 返回最终结果
    TM->>MA: 传递结果
    MA->>MA: 处理结果

5.2 上下文隔离

子代理有独立的上下文，不会继承：

  • 主代理的对话历史
  • 主代理加载的文件内容
  • 主代理的临时状态

子代理会继承：

  • 项目的 CLAUDE.md 规则
  • 代理配置文件
  • Skills 元数据

5.3 结果传递

子代理完成后，只有最终输出会返回给主代理：

graph LR
    SA[子代理
长篇分析过程...] -->|仅最终结果| MA[主代理]

这意味着：

  • 中间过程不可见
  • 需要在 prompt 中明确要求返回格式
  • 大量数据需要考虑压缩

6. 高级特性

6.1 并行代理调度

当多个任务相互独立时，可以并行执行：

graph TB
    Main[主代理] --> Task1[创建代理 1]
    Main --> Task2[创建代理 2]
    Main --> Task3[创建代理 3]
    
    Task1 --> Wait[等待所有完成]
    Task2 --> Wait
    Task3 --> Wait
    
    Wait --> Merge[合并结果]

最佳实践：

  • 最多同时创建 4 个代理
  • 确保任务真正独立
  • 结果需要手动合并

6.2 代理链

复杂任务可以通过代理链完成：

8. 最佳实践

8.1 代理设计原则

原则 说明
单一职责 每个代理专注一个领域
明确边界 清楚定义代理能做什么和不能做什么
输出规范 明确指定输出格式
失败处理 考虑代理失败的情况

8.2 何时使用代理

✅ 适合使用代理：

  • 任务可以并行执行
  • 需要隔离上下文
  • 需要专业化处理
  • 任务之间独立

❌ 不适合使用代理：

  • 简单的单步任务
  • 任务之间高度依赖
  • 需要共享大量上下文
  • 实时交互场景

9. 常见问题

Q: 代理之间可以直接通信吗？

A: 不能。代理之间是隔离的，只能通过主代理传递信息。如果需要协作，可以：

  1. 将一个代理的输出作为另一个代理的输入
  2. 使用主代理协调和汇总

Q: 代理可以访问主代理的对话历史吗？

A: 不能。代理有独立的上下文。需要共享的信息必须在 prompt 中明确传递。

Q: 代理的执行时间有限制吗？

A: 没有硬性限制，但代理会像主会话一样消耗 Token。长时间运行的代理应该考虑分解任务。

Q: 如何限制代理的工具访问？

A:

  1. 使用预定义的 subagent_type（如 explore、code-reviewer）
  2. 使用 readonly: true 参数
  3. 在代理配置文件中声明允许的工具

Q: 代理失败了怎么办？

A:

  1. 检查代理返回的错误信息
  2. 使用 resume 参数恢复并修正
  3. 简化任务或分解为更小的步骤

Q: 可以自定义代理类型吗？

A: 是的，在 .claude/agents/ 目录创建 .md 配置文件即可。然后在 Task 工具中通过 subagent_type 引用。
